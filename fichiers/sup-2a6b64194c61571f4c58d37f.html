Android — Supplément 7 : Intents explicites, implicites & Bundle

Un Intent est un message envoyé au système Android pour démarrer une Activity. explicite : on nomme la classe cible. implicite : on décrit une action et Android cherche l'application capable de la faire. Le Bundle transporte les données (extras).

Explicite ou implicite ?

      

        
ExpliciteImplicite

        
CibleUne classe précise : ProfilActivity::class.javaUne action (+ data, type) : ACTION_VIEW

        
Qui choisit ?Le développeurLe système, via les <intent-filter> des applis installées

        
Usage typiqueNaviguer entre les écrans de son applicationUtiliser une autre application : navigateur, téléphone, SMS, partage, carte…

        
Si personne ne répondImpossible si l'Activity est déclarée dans le ManifestActivityNotFoundException → try/catch

        
Plusieurs candidats—Boîte « Ouvrir avec » ou Intent.createChooser()

🎒 Le Bundle : types et méthodes

      

        
TypeEnvoyerRecevoir (dans la cible)

        
StringputExtra("nom", nom)getStringExtra("nom") → String?

        
IntputExtra("age", 20)getIntExtra("age", 0) ← valeur par défaut obligatoire

        
BooleanputExtra("ok", true)getBooleanExtra("ok", false)

        
DoubleputExtra("moy", 14.5)getDoubleExtra("moy", 0.0)

        
ArrayList<String>putStringArrayListExtra("mods", liste)getStringArrayListExtra("mods")

        
ObjetputExtra("st", stagiaire) (classe @Parcelize … : Parcelable)getParcelableExtra("st", Stagiaire::class.java) (API 33+)

        
Bundle entierputExtras(bundle)intent.extras → Bundle? puis getString("nom")

      

      
⚠️ Un Bundle est limité (~1 Mo partagé par la transaction) : on n'y met pas d'images ni de grosses listes, on passe plutôt un identifiant ou une URI.

      
💡 Bonne pratique : déclarez les clés comme constantes (const val EXTRA_NOM = "nom") dans un companion object pour éviter les fautes de frappe entre l'émetteur et le récepteur.

    

  

  

    

      
📥 Recevoir un Intent implicite : l'intent-filter

      

      
Pour qu'une Activity soit candidate, l'Intent doit passer les 3 tests : action (une des actions déclarées), catégorie (toutes les catégories de l'Intent déclarées — startActivity ajoute toujours DEFAULT) et data (scheme / host / mimeType compatibles).

    

    

      
↩️ Récupérer un résultat

      

      
L'ancien startActivityForResult() + onActivityResult() est déprécié : on utilise registerForActivityResult(ActivityResultContracts.StartActivityForResult()).
